01 / Project overview

Turning campus spaces into structured spatial information.

The Atlas is designed as a lightweight field-GIS data collector. A surveyor records campus assets as geographic features, adds descriptive attributes and a photograph, then reviews and exports the collected dataset.

Project objectives

  • Build a structured inventory of selected campus assets.
  • Capture locations and boundaries as points, lines and polygons.
  • Record names, categories, condition and other field attributes.
  • Review length, area and elevation observations.
  • Export open geospatial data for desktop GIS review and presentation.

Application specification

  • HTML5 application packaged for Android using the iAppyx native bridge.
  • GPS, camera, file storage, print and share integrations.
  • WGS 84 geographic coordinates (EPSG:4326); GeoJSON uses longitude, latitude order.
  • Esri satellite, street and topographic basemaps require an internet connection.
  • Local JSON database on the device, including saved photographs.
Scope: This is an academic mapping and asset-inventory platform for preliminary planning, teaching and project demonstration. It is not a substitute for survey-grade GNSS, cadastral control, differential levelling or engineering setting-out.

02 / Core capabilities

One workflow across six workspaces.

The supplied application build includes the following screens and functions.

01 / DASHBOARD

Project overview

Quick access to project status, campus links, survey shortcuts and counters for mapped assets, GPS vertices and photographs.

02 / GPS MAP

Map workspace

Switch satellite, street and topographic basemaps; navigate, centre on GPS, fit surveyed features and inspect map overlays.

03 / FIELD SURVEY

GPS data capture

Collect point, line or polygon geometry, capture GPS and altitude observations, enter attributes and attach a photograph.

04 / ANALYSIS

Elevation and spatial analysis

Review length, area, elevation summaries, elevation profile, route gradient and asset-category distribution.

05 / ASSETS

Campus asset register

Search, inspect, edit and delete saved features; export GeoJSON and CSV, or back up and restore the local database.

06 / REPORT

Project reporting

Refresh the live report and print or save a two-page A4 PDF with the current survey summary and data-quality notes.

05 / Technical details

Data model and interoperability.

Key details documented for the supplied application build.

ItemSpecification
GeometryPoint (1 vertex), LineString (2 or more vertices), Polygon (3 or more vertices; closing edge automatic).
Coordinate referenceWGS 84 (EPSG:4326); GeoJSON coordinate order is longitude, latitude (CRS84).
Asset categories16 categories covering buildings, departments, library, laboratory, seminar hall, hostel, canteen, roads, trees, drainage, parking, water, electricity, main gate, open space and other.
Walk captureA new vertex is added when the latest GPS fix is at least 1.0 metre from the previous vertex.
Local storageDevice-side JSON database (schema version 3); photographs are stored in the database.
ExportsGeoJSON feature data, CSV vertex rows, full JSON backup, shareable text summary and two-page A4 PDF.
QGIS deliveryLoad GeoJSON in QGIS; the guide recommends EPSG:32643 for projected length and area recalculation in the Mysuru area.
Data management note: The current build stores data locally on the device and does not provide cloud synchronisation. Take regular JSON backups. Photographs are included in the backup but are not embedded in GeoJSON or CSV exports.

06 / Accuracy and responsible use

Understand the limits of smartphone GIS.

Good field practice and honest reporting are part of a reliable engineering project.

Field quality practices

  • Capture outdoors with a clear sky view and allow the GPS fix to settle.
  • Record the GPS accuracy value and use a project threshold.
  • Recheck suspicious points, line spikes and polygon corners.
  • Use consistent asset names, IDs, condition values and remarks.
  • Back up the local database after each survey session.

Limitations to report

  • Consumer phone GNSS is not RTK or differential positioning.
  • Phone altitude is not differential levelling or a terrain model.
  • Basemap tiles require internet and imagery may be old or offset.
  • Calculated lengths, areas and gradients are indicative and need validation.
  • Do not use the app alone for cadastral, setting-out, structural or design decisions.
